# Клиентский путь и воронки (черновик)

Статус: **черновик** — утверждается с клиникой перед жёсткой автоматизацией.

## Цель CRM

Управление коммуникацией и прохождением пациента по клиентскому пути.
**Не** замена медицинской информационной системы (МИС).

## Основной объект

- **Пациент** — единая карточка (дедупликация по нормализованному телефону).
- **Обращение (Inquiry)** — конкретный вход в процесс с воронкой, этапом, ответственным и следующим действием.

Повторный контакт существующего пациента создаёт **новое обращение**, а не вторую персону.

## Воронки

### 1. Первичное обращение (`primary`)

Новое → контакт установлен → потребность определена → предложена запись → записан → подтверждён → пришёл / не пришёл → (потерян с причиной).

SLA первого контакта по умолчанию: **15 минут** на этапе «Новое обращение».

### 2. После первичного приёма (`aftercare`)

Первичный приём → план лечения → требуется продолжение → записан на этап → лечение начато / отложил / потерян.

### 3. Возврат (`return`)

Требуется контакт → связались → записан → пришёл / отказ с причиной.

## Инварианты

1. Новое открытое обращение всегда имеет **ответственного**, **nextAction** и задачу.
2. Закрытие «потерян / отказ» — только с кодом причины из классификатора.
3. Переход этапа — только по разрешённым `StageTransition`.
4. Отмена записи — причина из `CancelReason`, свободный текст только как комментарий.

## Роли

| Роль | Код | Доступ (MVP) |
|---|---|---|
| Оператор / администратор | `OPERATOR` | свои обращения и задачи |
| Руководитель подразделения | `MANAGER` | отдел, просрочки, конверсия |
| Управляющий | `DIRECTOR` | все подразделения, отклонения |
| Собственник | `OWNER` | KPI-дашборд |
| Системный админ | `ADMIN` | справочники, пользователи |

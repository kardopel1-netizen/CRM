# Синхронизация записи → этап воронки

При создании записи и смене статуса CRM **автоматически двигает этап** связанного обращения.

## Зачем

Оператор отмечает статус визита один раз — очередь, контроль и отчёты по воронке остаются согласованными с реальностью (без ручного «Записан / Подтверждён» в карточке).

## Соответствие статусов

| Статус записи | primary | aftercare | return |
|---|---|---|---|
| Предложена (`OFFERED`) | `offer_made` | `booked_next` | `booked` |
| Записан (`BOOKED`) | `booked` | `booked_next` | `booked` |
| Подтверждён (`CONFIRMED`) | `confirmed` | `booked_next` | `booked` |
| Пришёл (`ARRIVED`) | `arrived` (+ aftercare) | `treatment_started` | `arrived` |
| Неявка (`NO_SHOW`) | `no_show` | — | — |
| Перенос клиникой | `booked` | `booked_next` | `booked` |

Отмена пациентом **не** переводит в «потерян» автоматически (нужна причина из классификатора).

## Поведение

- Нет `inquiryId` → ничего не делаем.
- Уже нужный этап → no-op.
- Обращение `LOST` → не трогаем.
- При переходе подставляется `nextActionAt` из `slaMinutes` целевого этапа.
- Пишется аудит `appointment_stage_sync`.

Код: `src/server/inquiryStageSync.ts`.
